# Security and limitations

Use HTTPS in production, unique random `SESSION_SECRET` and `API_KEY_PEPPER`, strict file permissions on persistent WhatsApp auth state, least-privilege database credentials, protected backups, and regular dependency updates. API key secrets are returned once and stored as peppered SHA-256 digests. Session cookies are HttpOnly and SameSite=Lax. Production must set `COOKIE_SECURE=true`. The dashboard currently relies on same-site cookies and same-origin deployment; do not enable broad CORS for credentials. No webhook URL feature exists yet, so webhook SSRF/signature handling is not applicable.

Baileys is an unofficial WhatsApp Web client, not the official WhatsApp Business Platform. It can break when WhatsApp changes and use may be restricted by WhatsApp policies. Use only for opted-in communications and comply with applicable laws and WhatsApp terms. Do not use this project for unsolicited bulk messages, spam, or ban evasion. API key and session credentials must never be committed. The current adapter uses Baileys multi-file auth storage on a persistent volume; protect that volume and its backups. Encryption-at-rest for provider auth files, Cloud API, webhooks, media, admin management, and message acknowledgement delivery states remain future work.
